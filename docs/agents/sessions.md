# Sessions and their trust boundaries

What each Managed Agents session of this repo can do. Read it before you add a session kind, or before you change the token, the agent or the environment of one.

A GitHub Actions job starts every session. The job holds the API key `JUDGE_ANTHROPIC_API_KEY` and its own token, `github.token`. No session holds either one. The job reads each answer, decides in code, and writes to GitHub with its own token. The job of `factory.yml` also holds `FACTORY_SELF_TOKEN` and the private key of the App `dsf-repair`. No session holds either one.

The reader, the judge angles and the synthesis run on the judge's agent and the judge's environment. Their files are `.github/agents/judge.md` and `.github/agents/judge.environment.yaml`. The agent turns on the `agent_toolset_20260401` tools, with `web_fetch` and `web_search` off. The environment has the networking type `limited`, `allow_package_managers` true, and an empty `allowed_hosts`.

The factory's sessions run on the agent `dsf-builder` and the environment `dsf-builder`. Their files are `.github/agents/builder.md` and `.github/agents/builder.environment.yaml`, and `factory.yml` reads their ids from `claude-lock.json`. The agent has the same tools as the judge's agent. The environment has the networking type `limited`, `allow_package_managers` true, no packages, and the `allowed_hosts` `builds.dotnet.microsoft.com`, `dotnet.microsoft.com`, `api.nuget.org` and `globalcdn.nuget.org`. The session installs the SDK with `dotnet-install.sh` into `/root/.dotnet`. These sessions run when the factory runs with `--agent managed`, as `factory.yml` does since #379. With the default `--agent claude-code`, the agent phases run in a Docker sandbox on the runner, and no session starts.

A story that edits `.github/workflows/` needs the App permission `workflows: write`. Grant it in the settings of the App `dsf-repair`. Without it, GitHub refuses the push of a change to a workflow file.

Read each value off the code and the files under `.github/agents/`. Change this table in the pull request that changes the code it reads.

A run of the kind `reframe` under `--agent managed` reports that the public API of the base commit could not be listed. The API printer is in the Docker sandbox image alone, and the runner has none.

Under `--agent managed`, the gates run the agent's code on the runner, as the runner's user. The cleared environment of `HostShell` stops a careless leak. It does not stop a test that reads `/proc/<pid>/environ` of the factory process, which holds the job's secrets. The docker path has a pid namespace, and this path has none yet. The owner accepts the gap for the stories this repo builds. The fix is #391.
